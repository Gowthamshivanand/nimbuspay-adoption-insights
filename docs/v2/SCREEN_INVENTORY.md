# Screen inventory for the Figma hi-fi design and the React build

Taken from the live app (`app/static/app.js` at `acc2b65`). The design and the code are built from this list at the same time, so both use the **same screen IDs**. Exact fields, testids and API shapes are in PARITY_SPEC.md §1–3. Example data for every screen is the baseline scenario in `golden/golden_api.json` (use these real synthetic numbers in the mocks; never invent figures).

**Frames per screen:** Desktop 1440 (content max-width 1200), Tablet 834, Mobile 390. All 13 tabs must stay reachable on mobile: the tab bar becomes a horizontal scroll strip or a "More" menu (no tab removed). Tables become a horizontal scroll on mobile; nothing is hidden.
**Brand rules (current, keep unless the project owner approves a new palette):** white, charcoal #222222, accent orange #F28C28, teal #0F5E63 **only** for "verified", red #C62828 **only** for critical risk and errors. A "SYNTHETIC DATA" label is always visible in the header. No real NimbusPay (nimbuspay.io) branding.
**Components to design once:** header with role switch, tab bar, KPI card (ID, value, label, note; clickable), bar row, data table, tag/pill, outcome card, modal, chat bubbles (user, answer, caveat, refuse, clarify, streaming), chip, form fields (file, text, number, range, checkbox, select), buttons (primary, ghost, disabled), inline error text, empty-state text, loading text.
